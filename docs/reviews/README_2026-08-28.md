# Murderboard run — README.md

## The problem

turnstile makes one promise, in bold, in its first line: **a session hook cannot cost you
the session.** Everything in the repository is arranged to keep it. Eleven reviewers went
looking for the failure that promise denies, and constructed it six different ways against
the shipped code.

**Four of the five guarantees do not hold as written.** Not as a matter of interpretation —
each was reproduced by running the wrapper:

| guarantee | as stated | what the code does |
|---|---|---|
| 1 · an undeclared hook cannot block you | absolute | an undeclared hook printing the documented `permissionDecision: "deny"` object on stdout blocks anyway. Wrapper exit 0, **zero stderr — it never noticed** |
| 2 · a slow hook cannot kill the session | absolute | `cmd &` in a hook escapes the budget entirely; the grandchild inherits stdout and holds the caller until it dies. Also fails open ~50% of the time at 4.5s against the 5s default, from 1-second clock granularity |
| 3 · a killed hook is detected next time | absolute | the budget kill removes the breadcrumb on the way out; the `EXIT INT TERM` trap erases it on SIGTERM. Only a SIGKILL of the *wrapper* can latch it — which is not "a killed hook" |
| 4 · there is an off switch you can reach without a session | absolute | **holds.** The only guarantee no reviewer could break |
| 5 · it says when it did nothing | absolute | every skip line goes to stderr with exit 0, and stderr on exit 0 reaches the debug log only. Claude never sees it; the transcript never shows it |

The last row is the one that should decide what happens next. Guarantee 5 exists because
*"silence from a guard is indistinguishable from a guard that ran and passed, and this
estate has shipped that twice."* Measured against the platform's documented behaviour, an
**unwrapped** hook that dies on a missing `python` produces a visible transcript notice:
`Failed with non-blocking status code`. Wrapped in turnstile's default advisory mode, that
becomes exit 0 and a debug-log line nobody reads.

**Wrapping the seven-repository incident in turnstile would have made it more silent, not
less.** That is the repository's founding incident, and the tool built to answer it
currently deepens it.

### Why the selftests did not catch any of this

They cannot. Two reviewers independently broke the wrapper in ways the harness is blind to:

- Delete the breadcrumb-drop line entirely, so the latch can never be set by anything:
  `--selftest` → **PASS**. Assertions `3a`/`3b` `touch` the crumb by hand, so they exercise
  the *reaction* and have no visibility of *production*.
- Defang the watchdog (`sleep "$BUDGET"` → `sleep 999999`), leaving the grep-able string
  intact: a 15s hook at `budget 1` ran the full 15 seconds, the wrapper printed
  *"exceeded 1s and was killed"* — it was not — and `--selftest` → **PASS**. Assertion `2a`
  passes for the wrong reason, because the off-by-one `elapsed` clause covers for the
  absent kill.

`mutation_check.sh` misses both: its four wrapper mutations target the *reporting* branches,
not the crumb-drop line or the watchdog line.

So `README.md:115` — *"Every guarantee above has an assertion in `turnstile-run
--selftest`"* — is literally true and materially false. For guarantees 2 and 3 the
assertions cannot distinguish a working wrapper from a broken one. This is the repository's
own **"can the alarm ring?"** standard, applied to the repository, and failing.

## What this means for the document

**Every blocking finding is a claim the README makes about code that does not behave that
way.** That cannot be fixed in the README. There are two remedies and they are different
projects:

1. **Fix the code** so the five guarantees become true — process groups for the budget,
   stdout mediation for the declaration gate, crumb retention on the kill paths, a
   sub-second or kill-only budget test, and selftests with power over all five.
2. **Narrow the document** to what is delivered today — which means the headline promise
   becomes conditional, and the five guarantees each acquire a stated threat model.

Applying (2) alone would produce an honest README describing a tool that does less than it
was built to do. Applying (1) is a rewrite of `turnstile-run`. **No edits were made to
README.md in this run**, and its hash is unchanged. Per the process's escalation rule — *a
structural problem that patching will not retire* — this run stops at synthesis and hands
the decision back.

## What would validate it

Every blocking finding below is reproducible in under a minute against the shipped scripts.
The cheapest confirmation of the three that rest on the platform contract (guarantee 1 via
stdout, guarantee 5 via stderr visibility, gate mode on non-blocking events) is a single
end-to-end run inside a live Claude Code session; the reviewers verified them against the
documented contract plus the wrapper's demonstrated I/O, not against an observed block.
That gap is recorded as a residual ⚠.

## How it generalises

The pattern under nearly every finding here is one this repository already names and did
not escape: **a check that cannot fail, whose danger is that it passes.** It appears at
four levels in one small codebase — the selftest that fabricates its own precondition, the
mutation that targets the message instead of the mechanism, the inventory that reports
"no findings" against its own broken example, and `turnstile test` printing `all green`
having run nothing. A tool whose thesis is that silence and success must not look alike
produced four places where they do.

## Blocking findings

**B1 · Guarantee 1 is bypassed by the stdout protocol.** `turnstile-run:158` runs the hook
with stdout inherited and exits 0 at `:186`. Claude Code reads JSON from stdout on every
exit code; for non-2 codes the JSON alone decides. An undeclared hook emitting a deny
object blocks, and the wrapper prints nothing. (Roles 6, 4)

**B2 · Guarantee 5 is delivered on a channel nobody reads.** stderr + exit 0 → debug log
only. Strictly more silent than not wrapping the hook at all. (Role 6)

**B3 · Guarantee 3's latch is never set by the event it names.** `turnstile-run:169`
removes the crumb after a budget kill; the `:152` trap removes it on SIGTERM. Only a
SIGKILLed wrapper latches. (Roles 6, 4, 1)

**B4 · Guarantee 2 is escaped by a background child.** `kill -TERM "$hpid"` signals the
direct child only; grandchildren survive holding the inherited stdout pipe. Measured:
wrapper returns in 0s, caller blocked 20s, nothing printed. The README's own advice — *"put
the slow half behind `turnstile-run`"* — is the pattern that escapes it. (Roles 4, 1, 6)

**B5 · Guarantee 2 fails open non-deterministically.** `elapsed -ge BUDGET` on whole-second
`date +%s` stamps. Measured at the shipped default: 4.5s gate, 5s budget, 8 runs → 3
blocked, 5 failed open, each printing a false *"exceeded 5s and was killed"*. (Roles 6, 4)

**B6 · The budget does not start until stdin reaches EOF.** Order at `:150-156` is `mktemp`
→ `cat > PAYLOAD` → `trap` → crumb. A caller holding the pipe open hangs the wrapper before
the timer, before the crumb, and before the trap. Unbounded, and undetectable by guarantee
3. (Role 4)

**B7 · The two tools disagree on declaration precedence, producing a silent downgrade by
following the documented instructions.** `turnstile-run:137-147` is last-wins;
`turnstile:196` is gate-wins. `gate.template.sh:4` ships `# turnstile: advisory`, and
`turnstile:121` says to **add** a gate line. Result: `check` reports `MODE = gate` while the
wrapper runs it advisory and prints *"It has no '# turnstile: gate' line."* (Role 3)

**B8 · A hook that merely prints the declaration is promoted to gate.** A heredoc emitting
`# turnstile: gate` at column 0 arms an undeclared hook: exit 2, blocks. Fail-*closed*
promotion, in an estate whose house style quotes these lines in headers. (Role 1)

**B9 · The selftests for guarantees 2 and 3 cannot fail.** Both demonstrated by mutation:
crumb-drop deleted → PASS; watchdog defanged → PASS. (Role 4)

**B10 · The registration snippet omits `"type"`, documented as required.** `turnstile check`
run against that exact snippet reports "no findings", exit 0 — the inventory cannot see the
defect in the project's own documented example. `turnstile new` prints the same incomplete
form. (Role 10)

**B11 · `turnstile test` prints `all green` having tested nothing.** No `.claude/hooks/*.sh`
→ loop body never runs → `fail=0` → `all green`, exit 0. (Roles 3, and pre-run)

**B12 · Install cannot be executed as written**, and the README never names Claude Code as
the host product, never states the exit-code protocol guarantees 1 and 2 are entirely
about, and documents the off switch twice with no way back. (Roles 8, 10, 3)

**B13 · The estate already solved vendored-copy staleness and turnstile declines it
silently.** `cp` of four unstamped files, no freshness gate, in an estate that has a
stamp writer, a stamp reader, a hard gate, and a consumer manifest — and a recorded
incident of a consumer going 10 commits stale while ~17 worktrees branched from it. (Role 7)

## Major findings

- **The measurement table does not reproduce.** README says 7 SessionStart hooks; recomputed
  with the same floor-KB formula `turnstile check` uses gives **13**. README says 3
  PreToolUse hooks topping at 9KB; measured **10**, topping at **15KB** — the largest
  omitted. Counting basis unstated and inconsistent between rows. Every omission is a
  *large* hook, so the error understates the README's own argument. (Role 1)
- **Guarantees 2–5 already exist in the very files the README cites as the disease.** The
  39KB and 17KB SessionStart hooks in the evidence table are `interface2` and `murderboard`
  session-start hooks, which implement budget, breadcrumb-latch, `$HOME` off switch and
  degrade-loudly with the same names and reasoning, including *"In $HOME on purpose"*
  verbatim. Guarantee 1 is genuinely new. (Role 7)
- **Unacknowledged external prior art.** `claude-hook-guard`, published 2026-05-25, ships a
  5-second budget, a kill switch and did-the-guard-run logging — differing precisely in
  that it fails *closed*. That inversion is turnstile's actual contribution and the README
  never states it, because it never names what it differs from. (Role 2)
- **`turnstile test` calls the estate's own green tools red**, hardcoding `tail -1` = `PASS`
  against tools that print `all checks pass` / `7 passed, 0 failed`; `mutation_check.sh`
  pointed at one reports a false `MISSED`, the exact verdict its header forbids. (Role 7)
- **`turnstile check` false-alarms on both documented registration forms**
  (`${CLAUDE_PROJECT_DIR}`, exec form), reads 1 of 4 documented config locations, states a
  positive absence it cannot support, reports the estate's best-tested hook as untested, and
  parses the `timeout` field into `_t` and discards it — blind to the one field governing
  the ceiling that is the README's headline incident. (Roles 6, 7)
- **The global `~/.turnstile-off` regresses a per-repo lesson the reference already
  learned**: several repos share `$HOME`, so one shared latch lets a sick hook in one repo
  disable every other. (Role 7)
- **The command menu is a runnable `sh` fence ending in `./turnstile off`.** GitHub renders
  a copy button on it. (Role 10)
- **"No dependency to install" is false** for the command the README says to run first;
  `turnstile check` exits 127 with no turnstile-authored message when `python3` is absent —
  one paragraph after the missing-interpreter incident is made the headline evidence.
  (Roles 1, 4, 5, 6, 8)
- **Count and referent errors.** Five mutations, not four. Three self-catches in the repo's
  own commit message, not two — and of the two named, only one is a catch: the line-44
  fail-open was found by a human after an hour. *"Both of this repo's first two tools passed
  while completely broken"* points at `claim.sh` and `session_identity.sh` in short-course,
  neither of which is a turnstile tool. (Roles 1, 3, 5, 10)
- **The 60-second ceiling is real but not documented.** Traced to `initializeTimeoutMs:t=60000`
  in the VS Code extension; the hooks reference gives a 600s configurable default for
  SessionStart command hooks. The claim needs its source, or a ⚠. (Roles 1, 6, 4, 2)
- **Argument order.** The decision tree — *most things that feel like hooks are tests* — is
  the document's most valuable claim to its actual reader and arrives after the install
  instructions, so the reader meets "here is how to build a survivable hook" before "you
  probably should not build one." Install itself precedes the reasoning that produces it,
  and re-tells the seven-repos incident verbatim to stand up. (Role 11)
- **The document never shows what it promises.** Its thesis is *"it says out loud that
  nothing was checked"*; there is not one captured transcript of that output anywhere, and
  no diagram of a wrapper with six exit paths, whose guarantees are moreover numbered in the
  reverse of the order the code checks them. (Role 9)

## Residual ⚠

- **⚠ Not confirmed in a live session.** B1, B2 and gate-mode-on-non-blocking-events are
  verified against the documented platform contract plus the wrapper's demonstrated I/O, not
  against an observed block or transcript notice. Cheap to close; worth closing first.
- **⚠ Unsearched fields.** Functional-safety standards (IEC 61508 / ISO 26262), where
  turnstile's fail-operational choice is a named category; supervisor restart-limiting
  (systemd `StartLimitBurst`, Erlang/OTP restart intensity, CrashLoopBackOff), the closest
  prior art for guarantee 3; academic SE databases; patent literature; the individual Claude
  Code plugin marketplaces. An unsearched field is a residual, not an absence of prior art.
- **⚠ Nobody was asked.** No record exists in the estate of anyone having searched for
  existing Claude Code hook wrappers before turnstile was written. If the answer is "no",
  the `claude-hook-guard` overlap is independent reinvention and should be labelled as such;
  if "yes, and here is why it was rejected", that reasoning is the best paragraph the README
  does not have.
- **⚠ The stray-quote incident has no artifact.** Sole source is a same-author, same-day
  commit message; every `.claude/settings*.json` in the estate parses today.
- **⚠ Origin not reached** for Saltzer & Schroeder 1975, Nygard 2007 and DeMillo et al. 1978
  — attributed via secondary sources, texts not fetched.
